# 操作手册

## 使用前提

仅在当前任务授权对应操作时使用本手册。执行前确认项目根目录与适用规则，再定位本手册的相关部分。命令存在不代表执行成功，步骤不构成执行授权。

## 文档改动检查

适用场景：新增或修改项目基础文档。前置条件：已经知道本轮改动文件清单；不通过全项目扫描扩大范围。

1. 检查本轮修改片段及必要上下文，确认事实、计划、建议、决定与待核实事项的标签准确。
2. 对新增或改动的相对链接，仅解析其目标路径，确认文件存在；有章节锚点时只定位对应标题。
3. 对照 [职责路由](../../PROJECT_INDEX.md)，确认每类事实只有一个权威位置，其他位置只写摘要与链接。
4. 检查适用读写规则是否齐全、是否含个人设备私有路径或秘密、是否覆盖既有内容。
5. 将本次检查日期、对象、范围、方法和结果写入 [NOW.md 的证据入口](NOW.md)，前提是当前任务允许写入且结果有实质变化。

以下是供后续按需使用的 PowerShell 单文件链接目标检查示例；此示例本身未执行，不是项目构建命令：

```powershell
# 前置条件：当前目录已确认是项目根目录。
# 按本轮实际改动替换该路径，不枚举全项目。
Test-Path -LiteralPath './docs/context/NOW.md' -PathType Leaf
```

预期：目标存在返回 `True`。这只能证明路径存在，不能证明内容正确或功能可用。

## 产品操作

### 构建与测试

前置条件：Windows x64、.NET Framework 4.8 与框架自带 `csc.exe`，Windows PowerShell 5.1 或 PowerShell 7。框架及 UI Automation 程序集路径由 `build.ps1` 定位。无需安装第三方包。

```powershell
.\build.ps1 -Test
```

预期：编译输出 `dist/SelectionExplainer.exe`，模拟服务测试全部通过。测试进程退出；测试配置保留在忽略的 `work/`。本步骤不验证真实模型质量、全部桌面兼容性或发布结果。

### 运行与设置

执行 `dist/SelectionExplainer.exe`。首次设置、模型地址、托盘暂停及故障排查以 [使用指南](../guide.md) 为权威来源。不要为了文档检查启动桌面应用或读取用户设置。

### 发布打包

仅在获得版本发布授权、源码已提交且工作树干净时执行。前置条件除构建环境外，还包括 Git；`src/AssemblyInfo.cs` 中版本必须与参数一致。

```powershell
.\scripts\package-release.ps1 -Version 0.2.0
```

预期：先构建并测试，再向空的 `artifacts/` 写入 Windows x64 ZIP、源码 ZIP、源码 tar.gz、`release.json` 和 `SHA256SUMS`。源码归档来自 `HEAD`，不能据此宣称未提交改动已打包。目录非空时脚本拒绝覆盖；不得为重跑擅自删除用户成果。

手工比对 `Get-FileHash <文件> -Algorithm SHA256` 与校验清单。向远程推送 `v*` 标签会触发预览发布工作流；只有对应版本已获发布授权时才推送标签。工作流使用仓库临时令牌上传附件，不写持久密钥。发布后查看实际 Actions 结果和附件，再记录状态；配置存在不等于执行成功。

性能验证需分别覆盖安装包、磁盘、后台内存、CPU 和解释响应延迟，具体门槛见 [验证缺口](RISKS.md)。当前执行结果以 [NOW.md](NOW.md) 为准；本手册不作验证通过声明。
